FDA организует код приложения вокруг бизнес-доменов. Внутри каждого домена — одинаковый набор слоёв и файлов с предсказуемыми ролями. Структура самоподобна от компонентов до уровня всего приложения

## Принципы

<CardGrid>
  <Card title="Фрактальность" icon="left-caret">
    Одинаковая структура на всех уровнях: компонент → субдомен → домен. Открыв любой модуль, вы уже знаете, где что лежит
  </Card>
  <Card title="Инверсия зависимостей" icon="down-caret">
    Repo → Model → RPC → Controller → UI. Слои имеют низкую связность и линейную зависимость в одном направлении
  </Card>
  <Card title="Явные контракты" icon="approve-check-circle">
    Каждый файл — одна роль и один набор экспортов. Нарушение бросается в глаза на ревью
  </Card>
  <Card title="Framework-agnostic" icon="astro">
    SvelteKit, Next.js и Nuxt: меняются имена файлов, а слои и контракты остаются теми же
  </Card>
</CardGrid>

## Скилл для AI-агентов

Современные агенты могут писать FDA-код сами: устанавливаемый скилл учит агента собирать домены по контракту, ловить нарушения слоёв и адаптировать правила под ваш стек. Подробнее — в разделе [Скилл FDA для AI-агентов](/08-qwen-code-skill/).
