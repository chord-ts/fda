FDA организует приложение вокруг бизнес-доменов: `cart`, `auth`, `dashboard`. Внутри каждого домена — одинаковый набор слоёв и файлов с предсказуемыми ролями. Структура повторяется от компонента до всего приложения, поэтому проект растёт, не превращаясь в кашу.

## Основные принципы

<CardGrid stagger>
  <Card title="Фрактальность" icon="left-caret">
    Одинаковая структура на всех уровнях: компонент → подмодуль → домен. Открыв любой модуль, вы уже знаете, где что лежит
  </Card>
  <Card title="Разделение на слои" icon="down-caret">
    repo → model → RPC → контроллер → UI. Импорты смотрят только вниз — серверный код не утекает в браузер
  </Card>
  <Card title="Явные контракты" icon="approve-check-circle">
    Каждый файл — одна роль и один набор экспортов. Нарушение бросается в глаза на ревью
  </Card>
  <Card title="Framework-agnostic" icon="astro">
    SvelteKit, Next.js и Nuxt: меняются имена файлов, а слои и контракты остаются теми же
  </Card>
</CardGrid>
