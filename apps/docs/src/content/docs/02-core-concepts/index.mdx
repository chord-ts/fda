## 🌀 Фрактальность

**Фрактальность** — это принцип, при котором структура на одном уровне повторяется на всех других уровнях.

## Принципы
* Две категории для кода - функциональные слои (инфраструктура) и бизнес логика
* Бизнес логика должна быть инкапсулирована и определять домены
* Домены содержат функциональные слои и поддомены
* Это module first подход

### Термины внтури бизнес логики:
#### Домены
1. Задаются требованиями бизнеса
2. Прозрачны для разработчиков, менеджеров и заказчиков
3. Могут иметь публичное api для кросс-доменных связей
4. Определяют структуру приложения

#### Слои
1. Задаются разработчиками
2. Расширяются по мере возрастания функциональной сложности приложения
3. Данные перетекают как правило последовательно от слоя к слою
4. Отвечают за поток данных внутри доменов

## 🏗️ Business Logic vs Infrastructure

| Уровень | Путь | Описание |
|---------|------|----------|
| **Infrastructure** | `src/lib/*` | Код инфраструктуры, без бизнес-логики. Меняется крайне редко, в случае компонентов - их можно вынести в библиотеку |
| **Business Logic** | `src/routes/*` | Код с бизнес логикой. Меняется часто, может использовать код инфраструктуры |


## 📊 Слоистая архитектура (Layered Architecture)

Каждый домен/модуль имеет **строгое разделение на слои**. Верхние слои не используют нижние, но нижние используют соседний верхний. Направление потока данных сохраняется на всех слоях:

### Обобщение логических слоев:

| Слой | Файлы | Ответственность | Запреты |
|------|-------|-----------------|---------|
| **Repo** | `server/repo/*` | Подключение к внешним источникам | Нет бизнес-логики |
| **Model** | `model.server.ts`, `schema.ts` | Логика работы с данными | Богатые модели бизнес-логикой |
| **RPC** | `rpc.ts` | Использует модели и выступает как API | Не использует  |
| **Reactivity** | `state.ts`, `stores.ts` | Управление состоянием, реактивность | Нет прямых импортов внешних источников |
| **UI** | `+page.svelte`, `ui/` | Отображение, пользовательский ввод | Нет прямых импортов `repo/*` |
